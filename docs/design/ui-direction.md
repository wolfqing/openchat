# 界面方向

2026-10-28 定稿，第一版原型是 [ui-prototype.html](ui-prototype.html)（在线版：<https://claude.ai/artifact/QBFVpgvNTgxqF1RhRwDG18>，私有链接，需要从页面的 Share 菜单分享后别人才能打开）。

## 定位

bitchat 的特色是终端风格：等宽字体、IRC 命令。上游明确说这是刻意的身份选择（见 [phase0-findings.md](../phase0-findings.md)）。openchat 不做另一种外观风格，而是**让 mesh 网络看得见**。

依据是 Phase 0 的数据：用户最大的痛点是「消息收不到」和「附近没人」，界面类抱怨只占约两成。所以特色要长在这两个痛点上。

## 两层分开

| 层 | 内容 | 处理 |
|---|---|---|
| 内容层 | 消息正文、昵称 | 无衬线字体，正文 16sp、行高 1.5，不用等宽字体 |
| 网络层 | 信号带、送达路径、跳数、身份徽记 | 信号橙配等宽数字，只出现在固定位置 |

信号橙只用于网络层，所以它一出现就代表网络状态。

## 五个元素

1. **信号带**：每屏顶部同一位置，显示「直连 3 | 可达 11 | 12 秒前」。实心点在呼吸表示网是活的，空心点表示还在找。
2. **送达路径**：四个点依次是发出、被转发、送达、已读。用实心和空心区分，旁边始终有文字，不只靠颜色。失败时变红并给出重发。收到的消息标「经 N 跳」。
3. **身份徽记**：由公钥算出颜色和对称图案。昵称可以重名，徽记不行。点开就是指纹核对页。
4. **公开与私密分开**：附近频道是通栏公告，不用气泡，输入框前标「公开」。私信用气泡加带锁的蓝色。
5. **附近没人**：这是最常见的状态。用雷达表示 App 正在工作，下面列出能马上做的事，包括用快传把安装包发给身边的人。

## 视觉

- 亮色用略偏绿的灰白底。暗色用纯黑底，OLED 屏更省电，停电时电量很重要。
- 正文对比度按户外标准 ≥ 7:1。
- 动效只给网络层（脉冲、雷达扫描），并遵守系统的「减少动态效果」设置。

## 示例昵称

原型、截图、文档和测试数据里的示例昵称一律用历史人物，不用像真人的名字，以免被当成真实用户。中文版用张衡、李白、苏轼，英文版用 Lovelace、Darwin、Curie。演示重名的情况时，让两个人用同一个历史人物名。原型可以切换中文和英文。

每个名字后面都带 `#xxxx`，即 peer ID 的前四位十六进制，例如 `苏轼#e887` 和 `苏轼#0c3b`。消息列表、私信标题、信号带、指纹核对页、提示和输入框占位文字都带这个后缀，没有例外。后缀用等宽字体和次要文字色，紧贴在名字后面。

## 落地顺序

按 Phase 0 的结论，界面重做（Phase 1）要等真机实测后再决定。近期只落地 1、2、5：它们直接对应两个主要痛点，真机测试时也能用来看网络状态。3、4 和整体换肤留到真机结论出来以后。

需要协议层补的数据：每条消息的跳数（从 TTL 推算），「已转发」状态（收到自己消息被中继的回声），以及可达人数（直连之外通过公告包看到的 peer）。
